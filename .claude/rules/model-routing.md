# Automatic Model Routing & Quota Guard

Follow the routing table in `CLAUDE.md` / `AGENTS.md` Section 1 with synchronized subagent ceilings:
- **`explorer` (`haiku` / `flash`, `maxTurns: 15`):** Read-only search (`>3` files), caller tracing, impact mapping, and web research (`WebSearch`/`WebFetch`).
- **`implementer` (`sonnet` / `inherit`, `maxTurns: 40`, `maxReadsBeforeEdit: 10`):** Multi-file surgical implementation (`3+` files) + self-running Tier 1 & Tier 2 verification (`test` + `analyze`/`build`) before returning. **Mandatory `Opus Architect ➔ Sonnet Builder ➔ Opus Gatekeeper` Rule:** Even when the user prompt already lists exact target files and specs, if the slice creates or edits **`>= 3 files`**, the parent (`Opus`) MUST NOT write/edit those feature files directly in the main window—read 1–2 reference files (`2–4 turns`), delegate the `3+` file edits + test/typecheck runs to `Agent(subagent_type="implementer", model="sonnet")`, and review the result (`2–3 turns`). **No Blind Implementer Spawn:** If exact target file paths and line numbers are NOT yet known, locate them first with `explorer` (`haiku`/`flash`) or `2–4` scoped `Grep` calls—never spawn `implementer` (`self`) to wander the codebase, and enforce at most `10` read/search steps inside `implementer` before its first `Edit`/`Write`. **Prefer `Edit` Over Full-File `Write`:** For existing files, ALWAYS use targeted `Edit` blocks instead of full-file `Write` overwrites so Claude Code's Auto Mode classifier does not reject edits as destructive.
- **`debugger` (`sonnet` / `inherit`, `maxTurns: 18`):** Root-cause investigation under the `2-Strike` circuit breaker. **Investigation / Debug Ceiling (`<= 6` Main-Window Turns on 1–2 File Tasks):** Even when a bug fix or operational task is expected to touch only 1–2 files (e.g., SQL/RPC debug, Vercel/CI log tracing, UI tweak), if Parent (`Opus`) runs more than **6 read/inspect/debug tool calls** without a verified fix, **STOP investigating in the main window** and delegate root-cause tracing to `debugger (model="sonnet")` or log/code scanning to `explorer (model="haiku")`. Never let Parent `Opus` burn 20–100 turns on a 1–2 file debugging session.
- **`reviewer` (`sonnet` / `flash` for `browser` or `inherit` for full E2E, `maxTurns: 35`):** Live `browser` UI inspection, blocker-only diff review, or full milestone E2E verification. Never spawn a separate `reviewer` subagent just to run 1–3 CLI check/build/git commands.
- **Anti-Quota-Drain & No Main-Window Playwright/Web Bloat:** Do not spawn subagents for quick 1–2 known file edits (`<= 6` turns), config tweaks, or short shell checks. Never call `mcp__playwright__browser_*` or multi-page `WebFetch` inside the main window—always delegate browser/web tasks to `reviewer` or `explorer` so DOM snapshots do not pollute main context.
- **One Slice Per Prompt (No Unbounded Auto-Chaining):** Spawn at most 1–2 `implementer` subagents for the current slice, verify, report back to the user, and stop. Never auto-chain multiple sprint steps (`Step 1 ➔ Step 2 ➔ Step 3 ➔ Step 4`) continuously in a single turn without user confirmation.
- **Same-Feature Reuse (`< 40 turns`) vs Unrelated Task Isolation:** Reuse an existing `implementer` via `send_message` for small iterative follow-ups within the **same feature** while it is under `40 turns`; spawn a fresh subagent (`invoke_subagent` / `Agent`) when switching to an unrelated task/feature or once an agent exceeds `40 turns`.
- **Fresh Context Only (No Forking Parent History):** Always start new subagents with a clean context window and pass only the `<= 8 lines` `State-Delta` brief. Never fork or copy the bloated parent conversation history into a subagent.
- **Parallel Subagent Safety (Disjoint Files First):** When spawning 2+ `implementer` subagents concurrently, assign strictly non-overlapping target files (and let only the parent update `TASK_STATE.md` / `project-pitfalls.md`); use worktree isolation (`isolation: "worktree"` or `Workspace: "share"`) only when parallel tasks must touch overlapping files or run conflicting builds.
